# ФОРМА — мультибрендовый интернет-магазин обуви

Статический магазин: генератор на Python, без сборщиков и зависимостей.
Все страницы собираются из данных и компонентов — разметка нигде не дублируется.

**Демо:** https://pizko.github.io/shos/

---

## 1. Перед запуском: заполните `data/config.json`

Пустые поля не показываются пользователю, но без них часть сайта работает вхолостую.
`python3 build.py` печатает список незаполненного при каждой сборке.

| Поле | На что влияет |
|---|---|
| `contacts.phone` | телефон в шапке, подвале, на странице контактов |
| `contacts.email` | приём заявок (см. ниже), адрес в подвале |
| `contacts.wholesaleEmail` | адрес для B2B на Brand Partnerships |
| `forms.endpoint` | URL обработчика форм — предпочтительный способ приёма заявок |
| `company.legalName`, `inn`, `ogrn`, `legalAddress` | блок реквизитов на `/legal/` и разметка Organization |
| `domain` | подстановка в адреса вида `wholesale@<domain>` |
| `baseUrl` | canonical, Open Graph, `sitemap.xml`, `robots.txt` |

**Как отправляются заявки и заказы.** Если задан `forms.endpoint` — форма шлёт туда
JSON (`{subject, data}`); подойдёт Formspree, собственный обработчик или serverless-функция.
Если endpoint пуст, но заполнен `contacts.email` — форма собирает письмо через `mailto:`.
Если не заполнено ни то, ни другое, форма честно сообщает, что отправка не настроена.
Платёжный шлюз намеренно не подключён: на `/checkout/` готов UI и разметка способов
оплаты (карта, СБП, при получении) под дальнейшую интеграцию.

## 2. Сборка

```bash
python3 build.py
```

Генератор перезаписывает HTML в корне. Правьте `data/*.json` и шаблоны в `build/`,
а не собранные страницы.

## 3. Структура

```
build.py            сборка всех страниц
build/comp.py       компоненты: шапка, подвал, карточка, SEO-head, схемы, размерная сетка
tools/catalog.py    загрузка и выгрузка каталога через Excel/CSV
import/             шаблон и выгрузки каталога
data/config.json    компания, контакты, способы оплаты
data/brands.json    бренды
data/products.json  товары
data/content.json   тексты всех контентных и юридических страниц
assets/styles.css   исходное оформление (не трогать — в нём базовая эстетика)
assets/refine.css   витрина на первом экране
assets/shop.css     компоненты магазина
assets/shop.js      корзина, избранное, фильтры, поиск, галерея, формы
assets/data.js      генерируется сборкой: товары для клиентского кода
```

## 4. Каталог из Excel

Товары ведутся в таблице, а не в JSON. Модуль `tools/catalog.py`:

```bash
python3 tools/catalog.py template               # создать import/shablon.xlsx
python3 tools/catalog.py export                 # выгрузить текущий каталог в Excel
python3 tools/catalog.py import <файл> --build  # загрузить и сразу пересобрать сайт
```

Обычный цикл работы: `export` → правите файл в Excel → `import … --build`.
Поддерживаются `.xlsx` (нужен `openpyxl`) и `.csv` (без зависимостей,
разделитель определяется автоматически). Для CSV добавьте `--csv` к `template`
и `export`.

**Колонки.** Обязательные помечены звёздочкой в шапке: бренд, модель, артикул,
пол, категория, назначение, цвет, цена, материалы, страна, изображение,
описание, размеры. Необязательные: ID, код производителя, старая цена, новинка,
дата поступления. Порядок колонок произвольный, лишние игнорируются. На листе
«Справка» описано каждое поле; у пола, категории, цвета и бренда — выпадающие
списки.

**Размеры** задаются одной ячейкой в формате `размер:остаток` через запятую:
`40:3, 41:4, 42:0`. Остаток `0` показывает размер зачёркнутым.
**ID** можно не заполнять — он соберётся из бренда, модели и цвета и станет
адресом страницы товара. **Старая цена** больше текущей автоматически
переводит товар в Sale и рисует процент скидки.

**Проверка перед записью.** Файл разбирается целиком: несуществующий бренд,
нечисловая цена, неверный пол или категория, старая цена ниже текущей,
повторяющийся размер, дублирующийся артикул или ID, неверный формат даты —
всё выводится с номером строки. Если есть хотя бы одна ошибка, `data/products.json`
не перезаписывается. `--force` загрузит только корректные строки.
Перед каждой записью сохраняется `data/products.backup.json`.

Импорт **полностью заменяет** каталог: что в файле, то и на сайте.
Новый бренд сначала добавьте в `data/brands.json` — иначе строка не пройдёт проверку.

## 5. Как добавить товар вручную

Допишите объект в `data/products.json` и пересоберите. Поля:

```json
{
  "id": "brand-model-color", "brand": "<slug из brands.json>",
  "model": "Gel-Kayano 14", "sku": "FRM-XX-0000", "styleCode": "",
  "gender": "men|women|unisex", "category": "running|lifestyle|training",
  "purpose": "Бег по асфальту", "color": "black", "colorName": "Black / White",
  "price": 12990, "oldPrice": null, "isNew": false, "releasedAt": "2026-09-01",
  "materials": {"upper": "...", "sole": "..."}, "country": "Вьетнам",
  "image": "<id фото Unsplash или свой путь>",
  "description": "...",
  "sizes": [{"size": 42, "stock": 3}]
}
```

Карточка, страница товара, фильтры, поиск, sitemap и разметка Product подхватят
товар автоматически. Новый бренд — объект в `data/brands.json`, страница
`/brands/<slug>/` создастся сама.

## 6. Изображения

Сейчас фотографии подгружаются с Unsplash: каждому товару соответствует снимок
именно его бренда, галерея из пяти ракурсов получается кадрированием одного кадра
параметрами imgix. Это временное решение под собственную предметную съёмку —
замените значение `image` на свой путь, галерея соберётся так же.

## 7. Что намеренно не сделано

Личный кабинет с авторизацией, отзывы, рекомендательные блоки, программа
лояльности и email-рассылка (нужен бэкенд). `/account/` пока отдаёт форму
проверки статуса заказа и быстрые ссылки.

## 8. Содержание

На сайте нет и не должно появляться: формулировок «официальный дилер» и
«авторизованный продавец», выдуманных реквизитов, отзывов, наград и сертификатов,
логотипов брендов в блоке партнёров. Brand Partnerships говорит ровно то, что
есть: магазин расширяет портфель и открыт к оптовому сотрудничеству.
